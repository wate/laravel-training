Laravel学習用サンプルアプリ企画
===================================

目的
-------------------------

PHPフレームワーク「Laravel」の習得を目的として、
実際にサンプルアプリケーションを開発しながら学習を進める。

単純なTodoアプリやブログではなく、実際の業務や日常生活で役立つアプリケーションを題材にすることで、開発のモチベーションを維持し、継続的に機能拡張できるものを目指す。

アプリケーション候補
-------------------------

### ① プロジェクト・タスク管理システム

Redmineのようなチケット駆動型の管理システム。

#### 主な機能

- プロジェクト管理
- チケット・タスク管理
- ステータス・優先度管理
- 担当者・期限管理
- コメント・変更履歴

#### 学習できる技術

- CRUD
- Eloquent ORM
- テーブルリレーション
- 認証・認可
- 状態管理

### ② 個人事業主向け業務管理システム

個人事業主の日常業務を一元管理するシステム。

#### 主な機能

- 顧客・取引先管理
- 案件・契約管理
- 作業時間・工数管理
- 見積書・請求書管理
- 売上・入金管理

#### 学習できる技術

- データベース設計
- Eloquent ORM
- リレーション
- トランザクション
- 帳票生成・PDF出力
- データ集計

### ③ ナレッジ・技術情報管理システム

技術情報や学習内容を蓄積・整理するシステム。

#### 主な機能

- 技術メモ・記事の登録
- カテゴリ・タグ管理
- Markdown対応
- 全文検索
- 関連情報の紐付け

#### 学習できる技術

- ファイル管理
- 検索機能
- データリレーション
- Markdown処理

### ④ ワークフロー・業務自動化システム

業務上の申請・承認や処理フローを管理するシステム。

主な機能:

- ワークフロー定義
- 承認・却下処理
- 条件分岐
- 通知処理
- 実行履歴・監査ログ

学習できる技術:

- イベント
- リスナー
- キュー・ジョブ
- 状態管理
- 非同期処理

### ⑤ API・システム監視管理ツール

APIやサーバーなどの稼働状況を監視するシステム。

主な機能:

- APIエンドポイント管理
- 定期的な死活監視
- レスポンス時間記録
- 異常検知・通知
- 監視履歴・統計

学習できる技術:

- Laravel Scheduler
- HTTPクライアント
- Queue・Job
- 通知機能
- 外部API連携

おすすめのアプリケーション
--------------------------

### 個人事業主向け業務管理システム

今回の候補の中では、特にこのアプリケーションを推奨。

推奨する理由:

1. **実用性が高い**
    - 実際の仕事で利用できる可能性がある。
2. **Laravelの機能を幅広く経験できる**
    - 単純なCRUDだけでなく、業務ロジックまで実装できる。
3. **段階的に拡張できる**
    - 最初は小さく作り、必要に応じて機能を追加できる。

### システム構成イメージ

- ダッシュボード
    - 案件状況
    - 今月の売上
    - 未請求金額
- 顧客管理
    - 取引先情報
    - 連絡先情報
- 案件管理
    - 契約情報
    - 契約期間
    - 契約金額
- 作業管理
    - 作業時間
    - 作業履歴
- 請求管理
    - 請求書
    - 入金状況

段階的な実装計画
-------------------------

| Phase | 実装機能           | 学習テーマ             |
| ----- | ------------------ | ---------------------- |
| 1     | ログイン・顧客管理 | 認証、CRUD、Migration  |
| 2     | 案件管理           | Eloquent、リレーション |
| 3     | 作業時間管理       | バリデーション、集計   |
| 4     | 見積・請求管理     | トランザクション、PDF  |
| 5     | 通知・定期処理     | Mail、Queue、Scheduler |
| 6     | API公開            | API、認証、テスト      |

今後決めること
-------------------------

アプリケーションの具体的な方向性を決めるため、以下の項目を検討する。

### アプリの利用目的

- A:自分の仕事で実際に使う業務ツール
- B:日常生活で使える個人向けツール
- C:技術的な興味を満たす開発者向けツール
- D:実用性と技術学習の両方を重視

### Laravelで習得したい範囲

- A:Laravelの基本(MVC、CRUD、Eloquentなど)
- B:実務レベル(認証、認可、API、DB設計など)
- C:応用(Queue、イベント、Scheduler、テストなど)
- D:Laravelを使ったWebアプリ開発を一通り経験する

### フロントエンドの構成

- A:Laravel + Blade
- B:Laravel + Livewire
- C:Laravel + Vue.js / React
- D:未定

開発方針
-------------------------

- 実用性のあるアプリケーションを題材にする。
- 最初から大規模なシステムを作らず、段階的に機能を追加する。
- Laravelの機能を実際に使いながら理解する。
- 単に動くものを作るだけでなく、設計や実装方針も学習対象にする。
- 将来的に自分の業務で継続利用できる品質を目指す。

**最終目標:Laravelを使ったWebアプリケーションを、設計から実装・運用まで一通り経験する。**
