Laravel用語の言い換え表
=========================

概要
-------------------------

Laravel固有の用語は、一般的な設計用語やCakePHPの呼び方とずれることがあります。
このファイルでは、つまずきやすい用語を一般的な呼び方と並べて整理します。
CakePHPから移ってきた読者が、Laravelの資料を読み替えるための索引です。

用語の対応表
-------------------------

| Laravel用語            | 一般的な呼び方     | 実体                                           |
| ---------------------- | ------------------ | ---------------------------------------------- |
| サービスコンテナ       | DIコンテナ         | インスタンスの生成と保持を担う仕組み           |
| バインド               | 登録               | コンテナへ生成方法やインスタンスを登録する操作 |
| 解決(resolve)          | 取り出し           | 登録内容からインスタンスを用意する操作         |
| Facade                 | 静的プロキシ       | コンテナからの取り出しを隠す呼び出し窓口       |
| リアルタイムファサード | プロキシの自動生成 | `\Facades\`を付けたクラス名で使えるFacade      |
| サービスプロバイダ     | 起動時の登録処理   | バインドや初期化をまとめるクラス               |
| ヘルパ関数             | グローバル関数     | 名前空間を書かずに呼べる補助関数               |
| Eloquent               | ORM                | テーブルを1クラスとして扱う仕組み              |
| ミドルウェア           | フィルタ           | リクエストとレスポンスの間に挟まる処理         |
| ゲート/ポリシー        | 認可               | 操作の可否を判定する仕組み                     |
| コントラクト           | インターフェース   | 実装を持たず振る舞いだけを定義した型           |
| マクロ                 | 動的メソッド追加   | 既存クラスへ実行時にメソッドを足す仕組み       |
| スコープ               | クエリの再利用部品 | モデルに定義する共通の条件式                   |

CakePHPとの対応
-------------------------

CakePHPの列は5系の書き方を基準にしています。
4系以前では一部のAPIが異なります。
CakePHP 5ではAuthコンポーネントが削除され、認証はAuthenticationプラグインを使います。

| Laravel                         | CakePHPの近いもの                                | 用途                     |
| ------------------------------- | ------------------------------------------------ | ------------------------ |
| `config('app.name')`            | `Configure::read('App.name')`                    | 設定値の読み取り         |
| `Cache::get()` / `Cache::put()` | `Cache::read()` / `Cache::write()`               | キャッシュの読み書き     |
| `route('users.index')`          | `Router::url([...])`                             | URLの生成                |
| `auth()->user()`                | `$this->Authentication->getIdentity()`           | ログインユーザーの取得   |
| `request()->input('name')`      | `$this->request->getData('name')`                | 入力値の取得             |
| `old('name')`                   | `FormHelper`が自動で再表示                       | 再表示用の入力値         |
| `collect($array)`               | `collection($array)`                             | コレクションの生成       |
| `data_get($array, 'a.b')`       | `Hash::get($array, 'a.b')`                       | ネスト値の取得           |
| `Str::limit()`                  | `Text::truncate()`                               | 文字列の切り詰め         |
| `Str::slug()`                   | `Inflector::slug()`                              | URL用スラッグの生成      |
| `Hash::make()`                  | `DefaultPasswordHasher`                          | パスワードハッシュの生成 |
| `e($value)`                     | `h($value)`                                      | HTMLエスケープ           |
| `dump()` / `dd()`               | `debug()` / `dd()`                               | 変数の出力               |
| `session()->flash()`            | `$this->Flash->success()`                        | 一時メッセージの設定     |
| `User::query()`                 | `TableRegistry::getTableLocator()->get('Users')` | ORMの起点                |
| `app(Foo::class)`               | `Cake\Core\Container::get(Foo::class)`           | DIコンテナからの取り出し |

Facadeは静的プロキシ
-------------------------

LaravelのFacadeは、`Cache::get()`のようにクラス名と`::`で呼び出す書き方です。
裏ではコンテナから実体を取り出し、そのインスタンスのメソッドを呼んでいます。
`__callStatic()`が呼び出しを受け取り、`getFacadeRoot()`で得た実体へ処理を委譲します。

CakePHPの`Cache`や`Configure`のような静的クラスと、役割はよく似ています。
違いは、LaravelのFacade自体が処理を持たない点です。
毎回コンテナの実体へ転送するため、テストでは実体を差し替えられます。

サービスコンテナはDIコンテナ
-------------------------

Laravelのサービスコンテナは、一般的にDIコンテナと呼ばれるものです。
クラスの生成方法を登録し、必要になったときにインスタンスを返します。
コンストラクタの型宣言から依存を読み取り、自動で組み立てる機能も持ちます。
実体は`Illuminate\Container\Container`クラスです。

`app()`はDIコンテナの取り出し口
-------------------------

`app()`は、サービスコンテナからインスタンスを取り出すグローバル関数です。
引数なしで呼ぶとアプリケーション本体を返します。
クラス名や登録名を渡すと、コンテナがそのインスタンスを用意して返します。

| 書き方            | 返るもの                                                  |
| ----------------- | --------------------------------------------------------- |
| `app()`           | アプリケーション本体(`Illuminate\Foundation\Application`) |
| `app(Foo::class)` | Fooのインスタンス                                         |
| `app('cache')`    | `cache`という名前で登録されたインスタンス                 |

`resolve('cache')`は`app('cache')`の別名です。

使い分けの目安
-------------------------

Facadeとコンストラクタインジェクションは、どちらもコンテナから実体を得ます。
違いは依存の見え方にあります。

| 場面                             | 向いている書き方               |
| -------------------------------- | ------------------------------ |
| コントローラで標準機能を短く使う | Facade                         |
| 業務ロジックで依存を明示する     | コンストラクタインジェクション |
| テストで実体を差し替える         | コンストラクタインジェクション |
| 一度きりの確認や補助的な利用     | `app()`または`resolve()`       |
