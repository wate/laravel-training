Laravelプロジェクトのセットアップ
=================================

概要
-------------------------

プロジェクトの技術スタックを決めたうえで、`composer create-project`でスケルトンを作成し、開発を始められる状態まで整える手順をまとめます。
設定ファイルの細かい値ではなく、どの段階で何を整えるかを示します。

効率よく進めるための順序
-------------------------

上から順に進めます。
前の段階で決めた内容が後の段階に影響するためです。

- 規約は最小限で先に置きます: 以降の作業をAIへ任せる前提が整います
- 依存関係と実行環境を次に固めます: 以降の手順をその場で検証できます
- 検証手段は依存導入の直後に入れます: AIの出力をその場で確かめられます
- ドキュメントは最後に整備します: 設定が変わるたびに記述も変わるため、更新のやり直しを避けられます

技術スタックの決定
-------------------------

スケルトンを作成する前に、次の項目を決めます。
判断材料は[アプリ企画](../app_planning.md)を参考にしてください。

- アプリの目的と利用者
- 実装で習得したい範囲
- フロントエンドの構成
- データベースの種類

スケルトンの作成
-------------------------

```bash
composer create-project laravel/laravel example-app
cd example-app
```

作成直後にリポジトリを初期化し、基準となるコミットを作成します。
以降の変更を差分として追跡できるようになります。

技術スタックに応じた調整
-------------------------

既定の構成のままでは使い勝手が悪いため、決めた技術スタックに合わせて次の順で整えます。

1. エージェント環境を配置する
2. 依存関係を整理する
3. ローカル開発環境を用意する
4. フロントエンドの構成を合わせる
5. データベースとマイグレーションを確認する
6. コード品質ツールを設定する
7. Git管理を整える
8. 動作を確認する
9. ドキュメントを整備する

### エージェント環境を配置する

最初に置くのは、以降の作業をAIへ任せるための最小限の規約です。
細部の記述は、最後のドキュメント整備で完成させます。

- `.github/`: インストラクション・プロセスを配置します
- `.agents/skills`: スキル定義を配置し、`skills-lock.json`でバージョンを固定します
- `.ticket/`: Markdownベースのチケット管理を導入します
- `AGENTS.md`: エージェント向けのガイドラインを作成します

### 依存関係を整理する

バックエンドとフロントエンドの依存を、決定した技術スタックに合わせます。

- `composer.json`: 採用しないパッケージを削除し、必要なパッケージを追加します
- `package.json`: UIフレームワークやビルドツールを入れ替えます
- `scripts`: 開発・ビルド・テストの実行コマンドを揃えます

削除と追加は1パッケージずつ行い、都度`composer show`や`npm ls`で反映を確認します。

### ローカル開発環境を用意する

以降の手順をその場で確認できるよう、フロントエンドとデータベースより先に用意します。

- Dev Container: 言語・データベース・Webサーバーをまとめた構成を用意します
- 環境変数: サンプルは既定のまま残し、環境ごとの値は別ファイルで管理します
- 初期化: コンテナ起動時に依存導入・キー生成・マイグレーションを冪等に実行します
- テスト用DB: 開発用とは別のデータベースを用意し、テスト実行時に切り替えます

初回起動時はフロントエンドの設定が未完了のため、ビルドが失敗しても問題ありません。
構築手順の詳細は[ローカル開発環境](../local_environment.md)を参照してください。

### フロントエンドの構成を合わせる

- `vite.config.js`: 採用したUIフレームワークのエントリを追加し、削除した依存への参照を外します
- 開発サーバー: コンテナ外から接続できるよう`host`と`origin`を指定します
- アセット: UIフレームワークのアセットは生成物として扱い、コマンドで再生成できるようにします

設定を変えたら、アセットのビルドが通ることを確認します。

### データベースとマイグレーションを確認する

- 既定のマイグレーションが作成するテーブルを一覧化します
- 認証やセッションなど前提となるテーブルは残します
- 不要なテーブルに限り、対応するマイグレーションを削除します

テーブルの用途は、後から参照できる場所に記録します。

### コード品質ツールを設定する

開発中に品質を保つため、次の5種類の設定を整えます。

- 言語レベルの設定: 文字コード・改行コード・インデント・整形ルールを言語ごとに定義します
    - 作成するファイル: `.editorconfig`、`pint.json`、`.prettierrc.yml`、`.prettierignore`
- Lintの設定: 文書の構造と表記の規約を定義します
    - 作成するファイル: `.markdownlint.yml`
- 静的解析の設定: 解析の対象範囲と厳しさを定義します
    - 作成するファイル: `phpstan.neon`
    - 追加する依存: 静的解析ツールとLaravel向けの拡張
- テストの設定: 実行範囲とテスト用の接続先を定義します
    - 作成するファイル: `phpunit.xml`、`playwright.config.js`、`tests/e2e/`
- フックの設定: コミット時と編集時に整形・Lint・静的解析・秘密情報の検出を実行します
    - 作成するファイル: `.pre-commit-config.yaml`、`.github/hooks/post-edit-auto-fix/config.json`
    - 導入の時期: ツールを入れた直後に有効化し、以降の変更をその場で検証できるようにします

同じ役割のツールを二重に持たないよう、整形の担当は言語ごとに1つへ寄せます。

### Git管理を整える

- ブランチ方針: 作業用のブランチと、保護するブランチを決めます
- 除外の使い分け: チームで共有する除外は`.gitignore`、個人環境の除外は`.git/info/exclude`に書きます
- 生成物: ビルド成果物やフレームワークが出力するアセットはコミットせず、コマンドで再生成します
- 秘密情報: 環境変数ファイルや鍵はコミット対象から外します
- 属性: `.gitattributes`で改行コードや図表ファイルの扱いを定義します
- ステージング: 変更したファイルを個別に指定し、一括追加は避けます
- コミットの単位: 1つのコミットに1つの目的だけを含めます
- コミット前の確認: `git status`と差分を確認し、意図しないファイルが混ざっていないか確かめます

ブランチの運用方法は[Git運用フロー](../git_workflow.md)を参照してください。

### 動作を確認する

次の観点で確認し、失敗した場合は該当する段階へ戻ります。

1. 依存関係: パッケージの導入とアセットの生成がエラーなく完了する
2. 静的解析: 指摘が0件になる
3. 自動テスト: 単体テストと機能テストがすべて成功する
4. 起動確認: アプリが応答し、エラー画面にならない
5. E2E: 主要な画面の操作が成功する
6. フック: 設定したチェックがすべて成功する

確認後にドキュメントを整備すると、実際に動いている構成をそのまま記述できます。

### ドキュメントを整備する

設定と動作確認が終わった後に、最終的な状態に合わせて作成します。

- `docs/`: プロジェクト概要、技術スタック、ディレクトリ構造、コーディング規約を配置します
- `README.md`: 概要とセットアップ手順を記載します
- `AGENTS.md`: 手順1で最小限に記述した内容を、最終的な構成とコマンドに合わせて完成させます
- 記録の置き場: 判断や学習の記録を残す場所を、運用に合わせて決めます

本リポジトリでの設定内容
-------------------------

このリポジトリで実際に採用した構成と入手先です。

### エージェント環境

- スキル定義の入手先: [wate/agent-skills](https://github.com/wate/agent-skills)
- 復元方法: `skills-lock.json`を基に`npx skills experimental_install`を実行します
- 更新方法: `npx skills update -y`を実行します

### 技術スタック

- バックエンド: PHP 8.3、Laravel 13
- データベース: MariaDB 11(開発用は`app_dev`、テスト用は`app_test`)
- フロントエンド: Blade、HTMX、Vanilla JS、AdminLTE 4、Bootstrap 5.3
- ビルド: Vite

### ローカル開発環境

- 構成: Dev Container
- 入手先: [wate/ldeのDev Container設定](https://github.com/wate/lde/blob/master/.devcontainer/README.md)をベースにし、Laravel向けの初期化を`post_start.sh`へ追記しています
- ポート: Apache 8080、Vite 5173、Mailpit 8025・1025、MariaDB 3306

### 品質ツール

- 整形: `laravel`プリセットのPintと、Prettier
- Lint: markdownlint
- 静的解析: Larastanを追加したPHPStan(レベル5)
- フック: pre-commit

### テスト

- PHP: PHPUnit
- E2E: Playwright(chromium)
